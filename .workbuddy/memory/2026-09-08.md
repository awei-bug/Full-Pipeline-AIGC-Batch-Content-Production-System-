## 演示链路 sandbox 网络栈陷阱（2026-09-08 20:55+）

观察到的现象：用户/present_files 看不到已 listen 的 dev server。

原因：sandbox 把工作台网络栈跟 host 网络栈隔开。后台启动 dev server 时如果用 `&` + `nohup` + `disown` 或者 `Start-Process` detached，进程脱离 sandbox 网络栈，在 host 上 listen 但 sandbox 内的 curl / present_files / 内嵌浏览器都看不到。结果是 netstat 显示 LISTEN、host 上 curl 也能 200，工具栈自己却探测不到。

正确做法：
- 用 Bash 工具的 `run_in_background: true` 直接启动 dev server（不要在命令内部再加 nohup / & / disown）
- 这样进程和工具栈共一个网络命名空间，present_files 的 reachability 探测才会通过
- 如果已经 detach 了，kill 重启用 Bash 启动

另外 vite 模块在 apps/studio-web/node_modules 下未安装，只在 root node_modules 里有；启动时要 `cd apps/studio-web && node ../../node_modules/vite/bin/vite.js`。
