## 一键启动.bat 启动失败修复（Windows 启动链路）

现象：双击 `一键启动.bat` 起不来。定位方式：看 `.local-stack/*.err.log`，三个子进程
都报"该文件不具有 .ps1 扩展名"，`-File` 收到的路径被截断成 `F:\Python_code\内容生成`。

两层根因（均已修）：
1. `Start-Process -ArgumentList` 把数组按空格拼接且不自动加引号，而仓库根目录含空格
   （"内容生成 Multi-Agent 协同编排系统"），`-File` 的脚本路径在第一个空格处被截断。
   改为传入手工拼好的单一参数字符串并自行给路径加引号，涉及三处：
   `scripts/start-local-stack.ps1`、`dev.ps1` 的 shop 启动、`scripts/start-data-hub.ps1`。
2. 修复注释我最初写了中文，而这些 `.ps1` 全是**无 BOM 的 UTF-8**，PS 5.1 按 GBK 解码
   → 解析直接报"意外的标记"。已改回纯 ASCII 注释（仓库原有做法是用 `[char]0x...` 规避中文）。
   新增约束：这些 .ps1 文件必须保持纯 ASCII。

顺手加固 `一键启动.bat`：失败时打印三个 err 日志尾部；只在 state.json 存在时才开浏览器
（此前失败也会打开一个死地址）。

验证：直接调用 `scripts/start-local-stack.ps1`，三个服务全部通过健康检查并写出 state.json
（api 3100 / orchestrator 8110 / studio 5201）。沙箱会在命令结束后回收子进程，所以该轮
进程已死、端口已释放；已删除该轮产生的 state.json，用户双击可干净启动。

沙箱特有干扰：WorkBuddy 沙箱环境同时存在 HTTP_PROXY/HTTPS_PROXY 与 http_proxy/https_proxy
（仅大小写不同的重复键），`Start-Process` 必抛"已添加项。字典中的关键字"。用户环境无此重复。
测试前需先移除小写变体。

文档：`docs/deployment-runbook.md` 新增第 9 节「本地一键启动排障（Windows）」。
用户随后双击实测成功（13:35 起三个服务在 3100/8110/5201 正常监听）。

## 桌面应用化第二轮：单图标 + 托盘 + 关窗即退出

用户反馈「有两个图标（多一个停止内容创作平台）」，要的是「像微信 QQ：双击直接启动、后台有托盘、
关掉就整体退出」。据此把桌面应用从「两图标 + 手动停止」改为「单图标 + 托盘驻留 + 关窗即退出」。

改动：
- `scripts/launch-app.ps1` 重写为驻留式启动器：服务就绪 → 开窗口 → `System.Windows.Forms.NotifyIcon`
  托盘驻留（菜单「打开主窗口 / 退出应用」，双击托盘唤出窗口）→ 每 2 秒轮询该 profile 的浏览器进程，
  窗口消失即关停（关窗口进程 → `stop-local-stack.ps1` → 清 pid/state → 移除托盘 → 自身退出）。
  新增 `--disable-background-mode` 防止 Chrome 关窗后残留后台进程；新增测试参数 `-NoTray`、`-MaxWatchSeconds`。
- `scripts/install-app-shortcuts.ps1` 只创建一个桌面图标，并自动清理旧版留下的「停止内容创作平台.lnk」。
- `scripts/stop-app.ps1` 增加「先终止托盘 shell」步骤（防它与停止脚本同时关停）。
- `app-shell.vbs` 未改动。

修掉两个真实 bug：
1. `scripts/local-stack-common.ps1` 的 `Stop-ProcessTree([int]$Pid)`：`$Pid` 是 PowerShell 只读内置变量，
   参数绑定必然抛「无法覆盖变量 Pid」，导致「杀进程树」一直静默失效、只靠端口兜底。
   改用 `$ProcessId`（两处调用同步改）。
2. 实例检测不可靠：原实现要求进程命令行里出现 `launch-app.ps1`，经包装脚本调用时不成立，
   于是第二次双击会起第二个托盘、覆盖 pid 文件，并在退出时关掉第一个实例的窗口。
   改为 pid 文件记录 **pid + 进程启动时间（yyyyMMddHHmmss）**（防 pid 复用误判），pid 文件提前到
   服务启动前写入；检测到已有实例时改为「等它就绪再聚焦窗口」，不再抢占。

新增约定（已写入 runbook 第 10 节）：
- `.local-stack` 状态文件清理一律用 `[System.IO.File]::Delete()` 而非 `Remove-Item`：
  某些工具会把 Remove-Item 包装成回收站操作并在失败时中断脚本，导致后续步骤被跳过。
- PowerShell 脚本禁止用 `$Pid`/`$PID` 作参数名或循环变量名。
- 实例检测不要依赖命令行内容。

实测（沙箱内，headless 与带托盘两种模式各跑通一遍）：
- 冷启动 → 三端口就绪 → 窗口打开 →「app window detected」✓
- 托盘创建成功（「tray icon active」）✓
- 杀窗口进程 →「shutting down: app window closed」→「services stopped」→ pid / state.json / *-run.ps1 全清 ✓
- 第二次双击 →「another shell instance owns the app, focusing its window」，未覆盖 pid、未起第二个托盘 ✓
- `stop-app.ps1` →「tray shell stopped pid=16076」→「services stopped」✓
- 全部脚本 AST 语法检查通过、纯 ASCII 检查为 0；桌面现在只有 `内容创作平台.lnk` 与开始菜单一份。

未覆盖：wscript 那一层无法在工具沙箱里端到端模拟（安全策略禁止 Start-Process 调 LOLBin），
但 `app-shell.vbs` 未改动，且用户 17:07 的双击日志已证明该链路可用。

## 应用图标重做（更好看 + 更匹配）

用户反馈原图标不好看（原为 System.Drawing 画的 64px 括号字形）。做法：

1. 用 Pillow 生成候选：4 种构图（单星芒 / 星芒+内容线条 / 双星 / 星芒+圆环）× 多个星芒
   饱满度参数，除 256px 预览外还输出 16/24/32/48/64/128 的真实尺寸对比条逐个看图筛选。
2. 选定：圆角方形（radius 22.5%）+ 靛紫对角渐变（#6366F1 → #A855F7）+ 左上柔光 +
   白色四角星芒（R=0.33S，三次贝塞尔凹边 ctrl=0.115）。16px 下仍是清晰十字星，
   双星方案在 16px 会糊成噪点，已淘汰。
3. 新增可复现脚本 `scripts/make-app-icon.py`（1024 超采样 → 7 档尺寸 ICO，51KB）。
   ICO 由脚本**手工组装**：≤48px 用 32bpp BMP 帧，≥64px 用 PNG 帧（Windows 原生推荐组合）。
   Pillow 默认全用 PNG 帧；实测 System.Drawing 能加载但取 16x16 帧不稳，而 BMP 是 ICO 原生负载，
   `System.Drawing.Icon` 无条件支持。`launch-app.ps1` 的托盘改为优先取 16x16 帧、失败回退默认帧。
4. 输出两份：`public/favicon.ico`（浏览器标签）+ `public/app-icon.ico`（快捷方式与托盘）。
   **分文件是刻意的**：Windows 按路径缓存快捷方式图标，同名覆盖会继续显示旧图。
5. `install-app-shortcuts.ps1` 的 iconPath 改指 app-icon.ico；fallback 生成函数同步改为星芒
   （参数名从 `$path` 改为 `$IconFile`，避免与内部的路径变量冲突）；`launch-app.ps1` 的
   托盘图标也切到 app-icon.ico。
6. 重建快捷方式并核验：两份 .lnk 的 IconLocation 均为 app-icon.ico（UTF-16LE 存储），
   跑 `ie4uinit.exe -show` 刷新图标缓存。

归档：`demo/app-icon.png`（256px 预览）、`demo/app-icon-sizes.png`（7 档尺寸对比条）。
依赖：Pillow（已装在 managed venv）。

## 任务栏图标统一为 app-icon（WebView2 桌面壳）

用户反馈：桌面快捷方式与托盘图标已换成 app-icon，但**任务栏图标仍是浏览器图标**。

根因：工作台用 Chrome/Edge `--app` 窗口承载，任务栏图标来自该浏览器窗口（浏览器自身图标），
无法替换。桌面图标来自 .lnk、托盘来自 NotifyIcon，不受此限。

方案（用户选「真正桌面应用壳」）：用系统 WebView2 把工作台装进我们自己的 WinForms 窗口，
窗体 Icon 与托盘均加载 app-icon.ico，任务栏/托盘/桌面三处统一为 app-icon，单图标、关窗即退出。
首次运行在本机自动下载 WebView2 组件（NuGet 包，需联网一次；已确认装了 WebView2 Runtime v154），
失败自动回退到浏览器 `--app` 形态（launch-app.ps1）。

改动：
- 新增 `scripts/launch-app-shell.ps1`：复用 `dev.ps1 content` 拉起后端、`stop-local-stack.ps1` 停服；
  单实例检测（pid+启动时间，聚焦已有窗口用 user32 FindWindow）；`Ensure-WebView2` 下载/定位
  `Microsoft.Web.WebView2.WinForms.dll` + Core + `WebView2Loader.dll`（放 `app-shell/lib` 并加入 PATH）；
  `Add-Type` 编译内联 C# `AppShellForm`（WebView2 控件承载 `http://127.0.0.1:5173`，
  窗体 Icon = 托盘 = app-icon，托盘菜单 Open/Quit，关窗即退出）；WebView2 失败 catch → 删 pid → 调 `launch-app.ps1` 回退。
- `app-shell.vbs` 的 start 分支改调 `launch-app-shell.ps1`（stop 不变）。桌面 .lnk 仍指向 vbs，图标 app-icon，无需重建。

约束：文件纯 ASCII（C# 源码用双引号、标题用 code points 传入，规避 GBK 解码）；菜单项英文
（Open/Quit）规避 C# 中文；`$PID` 不用作变量名；状态清理用 `[System.IO.File]::Delete`。

验证：PowerShell AST 语法解析通过（SYNTAX_OK）。WebView2 实际渲染需用户本机双击验证
（工具沙箱无显示器/运行时，且禁 Add-Type/csc，无法在此跑 UI）。回退链路保留，不破坏现有可用形态。

风险：首次下载需本机联网；若本机 powershell 为 32 位则 x64 WebView2Loader 不匹配（多数 x64，失败即回退）。

## 修复：双击打不开（Mutex 替换 pid 单实例）

用户反馈：图标换成 app-icon 后双击「内容创作平台」反而打不开（之前 pid 方案的 launch-app.ps1 能开）。

根因（看 `.local-stack/app-shell.log` 两次双击均走 `another instance owns the app, focusing its window` 然后 exit）：
`launch-app-shell.ps1` 的单实例用 **pid 文件 + 启动时间** 判断，但持锁进程若卡在下载 WebView2
或异常退出，pid 文件残留 → 此后每次双击都误判「已有实例」→ 去 Focus 一个根本没出现的窗口 →
弹出 `False` 后退出，永久打不开。属 pid 文件单实例方案的固有死锁缺陷。

修复：
- 单实例改为 **`Global\ContentCreateAppShell` 命名 Mutex**：进程退出自动释放，绝不残留死锁。
- 聚焦分支改为轮询等窗口出现（最多 30s），避免「窗口还没出来就判定找不到」。
- 回退调用 `launch-app.ps1` 时加 `-Force`，避免回退再被任何单实例判断挡住。
- 删除 `Get-ShellRecord`/`Test-ShellAlive` 两个 pid 判断函数；清理残留 `app-shell.pid`。
- `launch-app.ps1` 仍保留自己的 pid 单实例（仅回退路径用到，正常双击不走它）。

验证：Powershell AST 语法解析 SYNTAX_OK。首次双击现会真正走到后端/WebView2 步骤
（首次联网下载 WebView2 组件，数秒~一分钟属正常加载）；若 WebView2 加载失败自动回退浏览器形态。
